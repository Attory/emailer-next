## Web server selection

Apache owned address-specific ports 80/443 while Nginx was active on a different
port. Selecting whichever service appeared active first configured the wrong
server. The repaired installer inspects TCP listener ownership, selects the
supported public-port owner, and matches its existing address bindings. If both
servers own public listeners or ownership is unknown, it stops for explicit
operator selection/review rather than guessing. Other virtual hosts remain
outside the Emailer configuration scope.

## Fresh database

The first browser Database step failed because migration metadata had never
been initialized. Existing integration tests started with an already migrated
database. The repaired setup service verifies restricted input credentials,
then initializes Doctrine metadata inside the existing setup lifecycle lock
before planning/migrating. A regression provisions a genuinely empty disposable
MariaDB schema, proves wrong credentials create no metadata, applies every
migration, verifies repeat configuration is idempotent, and checks permanent
setup-lock refusal.

## Recovery and restore evidence

The encrypted backup was verified and a real isolated restore passed. However,
the restore timestamp existed only in the isolated database, while live Doctor
queried the originating database. The repaired real restore can compare every
row/asset and issue a private authenticated receipt; interactive live recording
checks the exact retained backup and records the original drill time without
restoring live data. Unsigned earlier operator diagnostics must not be
converted into receipts: repeat the actual drill using the supported command.

The recovery package is exported through hidden human terminal input and kept
separately. Receipt evidence does not replace a recovery-passphrase drill,
independent custody, host isolation, or human approval. Mailpit acceptance
continues to produce a production-SMTP critical finding and sending remains
blocked; this repair introduces no sending exception.
